# F6 Package, upload and app shell (iOS)

## Summary

Turns one capture into the guide's package and gets it to the station without losing anything.
Assembles the folder layout, writes the manifest with SHA-256 for every file, never renames or
re-encodes originals, queues uploads while offline and resumes them. Also the app shell that
wires F2–F5 together, Entra sign-in, and the project list from the station.

## In scope

- Package layout from the contract (Original Exports by floor and capture id, Site Photos, Field
  Measurements, Source Register, Working Conversions, Issued Outputs).
- `manifest.json`: every file, role, sha256, bytes, generator, `derivedFrom` linking derived files
  to the originals they came from. Package is read-only once sealed; edits create a new revision.
- Upload: request session from the station (OpenAPI in contract), upload each file to Blob by SAS
  in 8 MB blocks, resume after app kill or network loss, verify server-side sha256 before marking
  done. Background URLSession. Nothing deleted from the phone until the station confirms.
- Swift package `StationClient` (separate from PackageKit): client generated from the OpenAPI document,
  token-provider protocol, project list with offline cache.
- Sign-in with Microsoft Entra (MSAL), tokens in Keychain only. Project list and address from
  the station's HUB lookup; offline cache of the last list.
- App shell (XcodeGen `ios/project.yml`): screens flow capture record → scan → photos → controls
  → checklist → review package → upload status, per the frozen design.
- `.apple-only` marker on app/MSAL targets; `PackageCore` (layout, manifest, hashing, upload
  state machine) is pure Swift and Linux-testable.
- Design v2 (Oct 21, 2026; artboards 2b and 2f; phone-capture, phone-package and compass specs):
  one `NavigationStack` with the Captures home at its root (In progress and Sealed rows from
  `CaptureLibrary`), the Capture overview between the field screens, and the package screens
  Package ready, Package status, Verdict received and Revision n, all in ChapterUI (Inter, Times
  display titles, the real logo). The visit is kept in `visit.json`; the station's answers in
  `<packageId>.station-status.json`. A revision n+1 uploads only added and changed files; the
  station carries the unchanged ones over by SHA-256. A verdict notification opens its package.
- Manifest 1.1.0: no package the v2 app seals holds the retired role `spatial_report_pdf` (the
  station makes the spatial report, F9); packages sealed by an older build (1.0.0) still upload
  and get a verdict.
- Field-test mode (Debug builds, `CHAPTER_FIELD_TEST = YES` in `Config/Local.xcconfig`): the real
  scan, camera and compass with the in-process stub station, so nothing leaves the phone
  (`ios/App/README.md`).

## Out of scope

- App Store listing. Android.

## Steps

- F6.1 Build the pure-Swift PackageCore: layout, manifest, sha256, sealing and revision rules, with tests.
- F6.2 Build the resumable upload state machine and the background URLSession transport, with resume tests.
- F6.3 Build Entra sign-in, the station client from the OpenAPI document and the project list with offline cache.
- F6.4 Build the XcodeGen app shell that wires F2–F5 screens into one flow, plus simulator UI tests using ReplaySession.
