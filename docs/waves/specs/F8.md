# F8 Acceptance checks

## Summary

Runs the guide's "when the station receives the package" checklist automatically and gives one of
the guide's three outcomes: ready for the stated preliminary task, usable with named limitations,
or blocked. Each finding names the source file, the rule, the measured value, and the next action.

## In scope

- Pure check library (npm workspace `@chapter/station-checks`), each check a function
  `(package) → findings` with severity `blocker | limitation | info`:
  1. Fingerprints: every file's sha256 equals the manifest.
  2. Nonempty and parseable per role (DXF, CSV, PDF, GLB/glTF, OBJ/MTL, LAS, JPEG/HEIC, JSON).
  3. Property match: capture-record address equals the HUB address after normalization; mismatch is a blocker.
  4. Units and scale: each field-control distance vs the plan geometry; pass if the difference is
     ≤ max(1%, 25.4 mm); 1–3% is a limitation; > 3% is a blocker for that floor.
  5. Up direction and orientation: GLB +Y up with a horizontal floor plane; LAS Z extents agree with
     ceiling heights; DXF in millimetres.
  6. Companions: glTF BIN and images, OBJ MTL and textures all resolve by relative path.
  7. DXF content type: plan entities only; meshes or point entities are flagged.
  8. LAS header: version, point format, counts and extents equal the data.
  9. Coverage: every captured room has at least one photo; omitted and inaccessible rooms are listed as limitations.
  10. Plausibility: ceiling 2.0–6.0 m, door width 0.6–1.5 m, window sill ≥ 0; outliers are limitations.
  11. Floor registration: floors share ≥ 2 landmarks in field controls; otherwise "floor alignment
      not established" is a limitation (separate capture origins are not evidence of alignment).
  12. Independence note: agreement between exports of the same capture is never counted as an
      independent measurement.
- Outcome rule: any blocker → blocked; else any limitation → limited; else ready.
- Entry point `runChecks(pkg: LoadedPackage, hubAddress: string): Verdict` (pure, no I/O). The worker
  that loads packages and stores verdicts is in F9.

## Out of scope

- Checking Polycam packages that have no Chapter manifest (later). Professional review or sign-off.

## Acceptance criteria

```yaml criteria
AC1: {text: "Every synthetic good fixture gets outcome ready", verify: "test:station/checks/test/good-fixtures.test.ts"}
AC2: {text: "Each broken fixture produces exactly the expected finding and outcome (empty file and wrong address blocked; 3%-off dimensions blocked; Z-up mesh and missing BIN limited or blocked as specified)", verify: "test:station/checks/test/broken-fixtures.test.ts"}
AC3: {text: "The 1% or 25.4 mm tolerance rule is applied exactly at its boundaries", verify: "test:station/checks/test/tolerance.test.ts"}
AC4: {text: "Every finding names file, rule, measured value and a next action", verify: "test:station/checks/test/finding-shape.test.ts"}
```

## Steps

- F8.1 Build the finding model, outcome rule and checks 1, 2, 6, 7 and 8 (file integrity and format).
- F8.2 Build checks 3, 4, 5, 10 and 11 (property, units, orientation, plausibility, floor registration) with the tolerance tests.
- F8.3 Build checks 9 and 12 (coverage and independence) and the fixture-driven good and broken test suites.
