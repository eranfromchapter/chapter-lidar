# F3 Plan exports (iOS)

## Summary

Writes the guide's plan files from a `CaptureModel`, on the phone, with no network: DXF floor
plan, room measurement CSV, the plan sheet PDF (Tabloid 11 x 17), and PNG/SVG previews. Pure
Swift + Foundation so every writer runs and tests on Linux. Since Design v2 (Oct 21, 2026) the
Spatial Report PDF is no longer written on the phone: the station makes the spatial report after
its checks (F9).

## In scope

- DXF: ASCII DXF R2013 (AC1027), units = millimetres (`$INSUNITS` 4), one file per floor. Layers
  `A-WALL`, `A-DOOR`, `A-GLAZ`, `A-OPEN`, `A-AREA` (room boundary polylines), `A-ANNO-TEXT` (room
  labels and areas), `A-FLOR-OBJ` (object footprints). Plan geometry only (no mesh, no points),
  so the guide's "inspect whether the DXF contains a plan, mesh or points" check is unambiguous.
- CSV (UTF-8, header row): floor, room id, room label, width_mm, length_mm, height_mm,
  floor_area_m2, perimeter_mm, door_count, window_count, and the same lengths in feet-inches.
  The file states that reported area is not a verified construction quantity.
- Plan sheet (Design v2, artboard 1b, plan-sheet spec): `plan-sheet.pdf`, role `plan_pdf`, one
  Tabloid 11 x 17 landscape page (1224 x 792 pt) per capture, made on the phone with no verdict.
  The plan is drawn at the first rung of the scale ladder at which it fits, 1:50, 1:100, 1:200
  (1:500 for an exterior capture), with a quarter turn tried at each rung; never fitted to the
  page; past the last rung it is cut at the frame with a footnote. Title block: the real Chapter
  logo, sheet number, title, project and address, HUB deal, capture id, captured date
  (America/New_York), device, mode, "Floor area, sum of rooms", rooms scanned and not scanned,
  legend, scale bar, the north arrow in its three compass states (or "Orientation: not
  verified" with the reason), the statement. Inter embedded; Times-Roman and Times-Italic for the
  title and tagline; Courier for ids, dimensions and the scale. Room fills by class (habitable,
  wet, other, outdoor) by the rule the station's spatial report also uses.
- Spatial Report PDF: retired on the phone (owner decision, Oct 21, 2026). `exportAll` writes
  five files (DXF, CSV, plan sheet, PNG, SVG); the station's spatial report (F9) replaces it.
- The colour Floorplan (`FloorplanWriter`, in-app Floorplan screen) keeps its look and writes the
  same bytes as before for the same input; `FloorplanWriter.Options.north` adds the north symbol
  when given.
- PNG (300 dpi equivalent, RGB) and SVG plan previews of the sheet's drawing, with no north
  symbol (the web shows orientation as text). PNG encoder implemented in pure Swift.
- A minimal pure-Swift PDF writer (lines, polylines, text, tables, Inter embedded) shared by the
  plan sheet and the colour Floorplan.
- `generator`/`generatorVersion` returned for each file so F6 can fill the manifest.

## Out of scope

- Mesh and point cloud (F4). Revit families or native BIM elements.

## Acceptance criteria

```yaml criteria
AC1: {text: "DXF for the two-room fixture has the seven layers and wall lengths within 1 mm of truth.json", verify: "cmd:swift test --package-path ios/Packages/PlanExport --filter DXFWriterTests"}
AC2: {text: "Generated DXF files pass an independent ezdxf audit with zero errors", verify: "cmd:scripts/verify-exports.sh dxf ios/Packages/PlanExport/.build/test-output"}
AC3: {text: "CSV room dimensions and areas match truth.json within 1 mm and 0.01 m2 for all four shapes", verify: "cmd:swift test --package-path ios/Packages/PlanExport --filter CSVWriterTests"}
AC4: {text: "The plan sheet is a valid one-page PDF 1.7 of 1224 x 792 pt and contains the address, the capture id and every room label (in capitals) as extractable text; qpdf and pdftotext accept every PDF", verify: "cmd:swift test --package-path ios/Packages/PlanExport --filter PlanSheetWriterTests && scripts/verify-exports.sh pdf ios/Packages/PlanExport/.build/test-output"}
AC5: {text: "The plan sheet's scale is from the ladder (1:50, 1:100, 1:200, 1:500 exterior); a 4.000 m room edge is 80.0 mm at 1:50 within 0.2 mm and the scale bar is exact", verify: "cmd:swift test --package-path ios/Packages/PlanExport --filter PlanSheetScaleTests"}
AC6: {text: "PNG decodes as a valid image and SVG is well-formed XML", verify: "cmd:scripts/verify-exports.sh preview ios/Packages/PlanExport/.build/test-output"}
AC7: {text: "The north arrow's states and captions follow contract/test-vectors/compass-states.json: verified and approximate draw the arrow turned with the drawing, not verified draws the box with its reason", verify: "cmd:swift test --package-path ios/Packages/PlanExport --filter NorthArrowTests"}
AC8: {text: "The colour Floorplan writes the same bytes as before (no north given)", verify: "cmd:swift test --package-path ios/Packages/PlanExport --filter FloorplanWriterTests"}
AC9: {text: "Sheet renders match the colour and grayscale goldens (sample-424 in its three north states, every fixture)", verify: "cmd:scripts/verify/plan-sheet-snapshot.sh"}
AC10: {text: "exportAll writes five files (no spatial-report.pdf); room names, fill classes, areas, totals and the north symbol of every fixture are written to fixtures/report-parity for the station's spatial report", verify: "cmd:swift test --package-path ios/Packages/PlanExport --filter 'ExportAllTests|ReportParityGoldenTests'"}
```

AC4, AC5 and AC7–AC10 are the plan-sheet spec's PS1–PS8 (Design v2, Oct 21, 2026); PS4's
vectors are the compass vectors (`contract/test-vectors/compass-states.json`).

## Steps

- F3.1 Build the DXF writer with layers, units and per-floor output, plus tests against fixtures.
- F3.2 Build the CSV writer with metric and imperial columns, plus tests.
- F3.3 Build the pure-Swift PDF writer and the plan PDF and Spatial Report PDF layouts, plus scale and text tests. (Design v2: the plan sheet replaces the plan PDF, and the Spatial Report PDF moves to the station, F9.)
- F3.4 Build the pure-Swift PNG encoder and the SVG writer for plan previews, plus tests.
