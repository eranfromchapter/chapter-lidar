# F3 Plan exports (iOS)

## Summary

Writes the guide's plan files from a `CaptureModel`, on the phone, with no network: DXF floor
plan, room measurement CSV, plan PDF, Spatial Report PDF, and PNG/SVG previews. Pure Swift +
Foundation so every writer runs and tests on Linux.

## In scope

- DXF: ASCII DXF R2013 (AC1027), units = millimetres (`$INSUNITS` 4), one file per floor. Layers
  `A-WALL`, `A-DOOR`, `A-GLAZ`, `A-OPEN`, `A-AREA` (room boundary polylines), `A-ANNO-TEXT` (room
  labels and areas), `A-FLOR-OBJ` (object footprints). Plan geometry only (no mesh, no points),
  so the guide's "inspect whether the DXF contains a plan, mesh or points" check is unambiguous.
- CSV (UTF-8, header row): floor, room id, room label, width_mm, length_mm, height_mm,
  floor_area_m2, perimeter_mm, door_count, window_count, and the same lengths in feet-inches.
  The file states that reported area is not a verified construction quantity.
- Plan PDF: scaled vector plan (1:50 or 1:100 chosen to fit Letter/A3), dimension strings, scale
  bar, north/orientation note, title block (address, project, floor, capture id, date, operator).
- Spatial Report PDF: per-room table (dimensions, area, height, openings, recognized objects) and
  capture metadata; states it is not a photo survey.
- PNG (300 dpi equivalent) and SVG plan previews. PNG encoder implemented in pure Swift.
- A minimal pure-Swift PDF writer (lines, polylines, text, tables) shared by both PDFs.
- `generator`/`generatorVersion` returned for each file so F6 can fill the manifest.

## Out of scope

- Mesh and point cloud (F4). Revit families or native BIM elements.

## Acceptance criteria

```yaml criteria
AC1: {text: "DXF for the two-room fixture has the seven layers and wall lengths within 1 mm of truth.json", verify: "cmd:swift test --package-path ios/Packages/PlanExport --filter DXFWriterTests"}
AC2: {text: "Generated DXF files pass an independent ezdxf audit with zero errors", verify: "cmd:scripts/verify-exports.sh dxf ios/Packages/PlanExport/.build/test-output"}
AC3: {text: "CSV room dimensions and areas match truth.json within 1 mm and 0.01 m2 for all four shapes", verify: "cmd:swift test --package-path ios/Packages/PlanExport --filter CSVWriterTests"}
AC4: {text: "Both PDFs are valid PDF 1.7, contain the address, capture id and every room label as extractable text", verify: "cmd:scripts/verify-exports.sh pdf ios/Packages/PlanExport/.build/test-output"}
AC5: {text: "The plan PDF scale bar is correct: a 4.000 m wall measures 80.0 mm at 1:50 within 0.2 mm", verify: "cmd:swift test --package-path ios/Packages/PlanExport --filter PlanScaleTests"}
AC6: {text: "PNG decodes as a valid image and SVG is well-formed XML", verify: "cmd:scripts/verify-exports.sh preview ios/Packages/PlanExport/.build/test-output"}
```

## Steps

- F3.1 Build the DXF writer with layers, units and per-floor output, plus tests against fixtures.
- F3.2 Build the CSV writer with metric and imperial columns, plus tests.
- F3.3 Build the pure-Swift PDF writer and the plan PDF and Spatial Report PDF layouts, plus scale and text tests.
- F3.4 Build the pure-Swift PNG encoder and the SVG writer for plan previews, plus tests.
