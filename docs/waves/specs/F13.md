# F13 Local test sign-in

## Summary

Added by the orchestrator in wave 5 (plan gap). The local station stack signs users in with
Microsoft Entra, so end-to-end tests on a laptop or CI runner (F6.AC4, later web and worker tests)
cannot get a token. A tiny local identity service issues short-lived test tokens that the local
API accepts. It never runs outside the local stack.

## In scope

- npm workspace `@chapter/station-dev-idp` in `station/dev-idp`, plain Node (built-ins only, no
  runtime dependencies), run by the compose file with the pinned Node image.
- Generates a fresh RSA key at start (never written to disk). Serves `GET /keys` (JWKS) and
  `POST /token` with JSON `{"roles": ["capture"|"bim"|"admin", ...], "sub"?: string, "name"?: string}`,
  answering `{"access_token", "token_type": "Bearer", "expires_in"}`. Tokens are RS256 and carry
  every claim the station's auth plugin checks (issuer, audience, tenant, roles, subject, name,
  exp/nbf/iat), valid at most 1 hour.
- Refuses to start when NODE_ENV is production. Listens on port 8090; the compose file publishes it
  on 127.0.0.1 only.
- Integration edits (orchestrator, W5): a `dev-idp` service in `station/api/docker-compose.yml`
  and, in `station/api/.env.example`, ENTRA_ISSUER and ENTRA_JWKS_URL pointing at dev-idp.

## Out of scope

- Any use in Azure. Interactive sign-in pages.
