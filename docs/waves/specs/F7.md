# F7 Station API

## Summary

The receiving end. A TypeScript service on Azure Container Apps that signs users in with
Microsoft Entra, looks up HUB projects, hands out upload sessions to immutable Blob storage,
verifies every file's sha256 server side, registers packages, and owns the whole Postgres schema
(including the tables F8, F9 and F10 use) so migrations have one owner and one order.

## In scope

- Fastify + TypeScript, npm workspace `@chapter/station-api`, implements `contract/openapi/station.yaml`.
- Routes live in `src/routes/<area>/index.ts` and are auto-registered (@fastify/autoload), so no
  phase edits a shared route table. Each route area ships its own `openapi-conformance.<area>.test.ts`.
- Auth: Entra ID JWT validation (issuer, audience, tenant "Chapter Main", signature via JWKS);
  roles `capture` (field team), `bim` (operators), `admin`. Every route requires a role.
- HUB lookup: list projects/deals and the confirmed address through a `HubClient` interface (the
  live implementation calls the HUB REST API with a service credential from Key Vault; a fake is
  used in tests). Cached for 10 minutes.
- Upload sessions: create package (capture id, dealId, revision), return per-file write-only SAS
  (block blob, 30-minute expiry) into container `originals` with immutability policy; `complete`
  recomputes sha256 server side and rejects mismatches; `seal` checks every manifest file is
  present and sets status `checks-queued` and inserts a job row.
- Postgres schema and migrations (`station/db/migrations`, node-pg-migrate, forward-only):
  projects_cache, packages, package_files, jobs (SKIP LOCKED queue), check_runs, check_results,
  verdicts, hub_publications, modeling_decisions, audit_log.
- Read routes: packages by dealId, package detail, verdict, signed short-lived download links
  for `bim` role; decision log create/list.
- Database sign-in (decided by Eran 2026-10-17): in Azure the station connects to Postgres with a
  short-lived Microsoft Entra access token for its managed identity (no database password anywhere);
  locally it uses DATABASE_URL against the compose Postgres.
- HUB live client settings live in core config: HUB_BASE_URL and HUB_SERVICE_CREDENTIAL (Key Vault secretRef).
- Every write goes to `audit_log` (who, what, when). No secret is logged.
- `station/api/scripts/local-up.sh`: docker compose with Postgres, Azurite and the API, fake HUB.
- Dockerfile for the API image.

## Out of scope

- Running checks (F8). Publishing to the HUB (F9).

## Steps

- F7.1 Scaffold the Fastify service with route autoload, config from env/Key Vault references, health route, Entra JWT auth plugin with roles, audit-log helper, Dockerfile and local-up script.
- F7.2 Write the forward-only migrations for every station table and the migrate:check script.
- F7.3 Build the HubClient interface with live and fake implementations and the project routes.
- F7.4 Build upload sessions, write-only SAS, server-side sha256 verification, immutability and sealing with job creation.
- F7.5 Build the package and verdict read routes, signed download links for the bim role, and the decision log routes.
