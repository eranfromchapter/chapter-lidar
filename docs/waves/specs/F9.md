# F9 Pipeline worker and HUB publish

## Summary

Puts the result where the team already works. After the verdict, the station writes the spatial
report PDF and uploads it, the manifest and the plan files into the project's HUB Files tab, and
links the large files (mesh, LAS, photos) that exceed the HUB's 50 MB upload limit. Since Design
v2 (Oct 21, 2026) the spatial report is made here, on the station after the checks; it replaces
the station's verdict report and the phone's retired Spatial Report PDF.

## In scope

- Worker (npm workspace `@chapter/station-worker`, own container): polls `jobs` with SKIP LOCKED;
  `checks` jobs load the sealed files from Blob, call F8 `runChecks`, write check_runs, check_results
  and verdicts, set the package status and enqueue a `publish` job; `publish` jobs call HubPublisher.
  Idempotent: re-running a job replaces its own run.

- `HubPublisher` (npm workspace `@chapter/station-hub`): uploads through
  `POST /api/projects/{dealId}/document-media/upload` (multipart field `files`), folder
  `Capture/<floor>/<captureId>/r<revision>`. Uses the project's sales `dealId`, never the project record id.
- Files sent: the spatial report PDF (station, `spatial-report-{verdictId}.pdf`) and
  manifest.json to `Capture/{visitId}/r{revision}`; per capture the plan DXF, rooms CSV, plan sheet
  PDF and plan PNG to `Capture/{areaKey}/{captureId}/r{revision}`. Files over 45 MB are not sent;
  the report lists them with station download links that require Entra sign-in (no public links).
  The phone's retired Spatial Report PDF (`spatial_report_pdf`, legacy 1.0.0 packages only) is
  never uploaded; it is listed with a station link like the other files the HUB does not get.
- Spatial report PDF (pdfkit, spatial-report spec, Design v2 artboards 1f–1ac): Letter landscape
  pages with the real Chapter logo and Inter embedded (Times-Roman titles, Courier ids): cover
  with the outcome in plain words, the plan of each floor, the totals and the capture; the plan
  page of each floor; the room schedule; the capture checks pages (every check, finding,
  limitation and next action in the words the web uses); a page per room; photo pages (photos
  reduced to 356 x 444 px with EXIF and GPS stripped); package record pages (every file with
  SHA-256 and where it is); the statement that it is not a certification of any property model
  or measurement on every page. Room numbers, fills, the floor area (sum of rooms) and the north
  arrow agree with the phone's plan sheet. Dates in `REPORT_TIME_ZONE` (America/New_York). The
  worker stores the PDF in the `reports` container with a `spatial_reports` row; the web
  downloads it through `GET /packages/{packageId}/spatial-report`.
- Idempotent: `hub_publications` row per package revision; a retry never duplicates files.
  Exponential backoff on 429/5xx, max 5 attempts, then status `publish-failed` with the error.
- After upload, verify through the HUB document search that each file is present.
- Fake HUB server for tests that records requests and enforces the 50 MB cap and dealId format.

## Out of scope

- Writing to HUB tasks, notes or phases (later, once the routes are confirmed).
