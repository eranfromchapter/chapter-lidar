# F9 Pipeline worker and HUB publish

## Summary

Puts the result where the team already works. After the verdict, the station writes a verdict
report PDF and uploads it, the manifest and the plan files into the project's HUB Files tab, and
links the large files (mesh, LAS, photos) that exceed the HUB's 50 MB upload limit.

## In scope

- Worker (npm workspace `@chapter/station-worker`, own container): polls `jobs` with SKIP LOCKED;
  `checks` jobs load the sealed files from Blob, call F8 `runChecks`, write check_runs, check_results
  and verdicts, set the package status and enqueue a `publish` job; `publish` jobs call HubPublisher.
  Idempotent: re-running a job replaces its own run.

- `HubPublisher` (npm workspace `@chapter/station-hub`): uploads through
  `POST /api/projects/{dealId}/document-media/upload` (multipart field `files`), folder
  `Capture/<floor>/<captureId>/r<revision>`. Uses the project's sales `dealId`, never the project record id.
- Files sent: verdict report PDF, manifest.json, plan DXF, rooms CSV, plan PDF, Spatial Report PDF,
  plan PNG. Files over 45 MB are not sent; the report lists them with station download links that
  require Entra sign-in (no public links).
- Verdict report PDF (pdfkit): outcome in plain words, findings table, limitations, next actions,
  capture record, file list with sha256, statement that it is not certification of measurements.
- Idempotent: `hub_publications` row per package revision; a retry never duplicates files.
  Exponential backoff on 429/5xx, max 5 attempts, then status `publish-failed` with the error.
- After upload, verify through the HUB document search that each file is present.
- Fake HUB server for tests that records requests and enforces the 50 MB cap and dealId format.

## Out of scope

- Writing to HUB tasks, notes or phases (later, once the routes are confirmed).
