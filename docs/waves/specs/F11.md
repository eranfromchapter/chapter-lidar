# F11 Test fixtures

## Summary

Phones cannot scan in CI, so every export writer and every station check is tested against
fixtures. This feature builds a deterministic generator of synthetic captures with known
dimensions, the folder where real recorded captures are added later, and a sanitized set of
reference packages that mirror Chapter's past Polycam intakes.

## In scope

- `fixtures/generator/` (TypeScript, npm workspace `@chapter/fixtures`): builds `CaptureModel` JSON for
  known shapes: 4.000 x 3.000 m box room (2.700 m ceiling); L-shaped room; two-room apartment with
  one door and two windows; two-floor house with a stair void and two shared landmarks; a depth
  sample set (points on those surfaces, with seeded noise of 5 mm) as a binary file.
- For each shape, a synthetic raw RoomPlan file in the `CapturedRoom`/`CapturedStructure` Codable
  JSON shape (walls, doors, windows, openings, objects; `dimensions` and 4x4 `transform`), so the
  F2 mapping can be tested without a device.
- Each synthetic fixture ships `truth.json` with exact dimensions, areas and opening sizes.
- Each fixture ships a matching `field-controls.json` (two perpendicular long distances per floor,
  ceiling heights, opening sizes, floor-to-floor level, landmarks).
- Minimal reference GLB and LAS files for each synthetic fixture, written by the generator, so
  station checks can be tested before the phone writers exist.
- Broken fixtures for negative checks: empty file, wrong address, inches labelled as metres, Z-up
  mesh, missing glTF BIN companion, LAS with bad header, dimensions 3% off the controls.
- `fixtures/recorded/README.md` with the exact procedure for the one human recording scan and the
  file layout the debug build exports (raw RoomPlan JSON + depth samples). Empty until recorded.
- `fixtures/reference/`: structure of past intake packages (24 Shawnee Road, 618 Valley Street,
  1500 Bay Road 1462) as manifests describing which roles each contained; real files are pulled
  from SharePoint by `fixtures/reference/fetch.sh` only when credentials exist, never committed.

## Out of scope

- Real customer files in git. Personal information in fixtures.

## Acceptance criteria

```yaml criteria
AC1: {text: "The generator is deterministic: two runs produce byte-identical fixtures", verify: "test:fixtures/generator/test/determinism.test.ts"}
AC2: {text: "Every generated CaptureModel and field-controls file validates against the F1 schemas", verify: "test:fixtures/generator/test/schema.test.ts"}
AC3: {text: "truth.json dimensions match the generated geometry to within 0.1 mm", verify: "test:fixtures/generator/test/truth.test.ts"}
AC4: {text: "Each broken fixture is labelled with the single defect it contains", verify: "test:fixtures/generator/test/broken.test.ts"}
AC5: {text: "No committed fixture contains an email, phone number or a real street address", verify: "cmd:node fixtures/generator/scripts/scan-pii.mjs fixtures"}
```

- F11.1 Build the synthetic CaptureModel and depth-sample generator with truth.json and field-controls.json for the four shapes.
- F11.2 Build the broken fixtures and the PII scan script.
- F11.3 Write the recorded-capture procedure and the reference package manifests with the credential-gated fetch script.
